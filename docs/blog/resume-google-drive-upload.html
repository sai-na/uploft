Can you resume a Google Drive upload after it stops?

Published 29 October 2026 · Updated 29 October 2026 · By Sai Nath

Not from Drive's website once the tab is gone: an upload there lives in its tab, so after the tab closes or Chrome restarts you upload the file again. Drive itself can resume: its resumable uploads continue from the last byte received, for up to a week, and uploaders built on them, such as Uploft, carry on.

This guide comes from the maker of Uploft, the Chrome extension mentioned below. Google's limits and steps link to Google's own pages and were checked on 29 October 2026; what the extension does comes from its source code.

Why does my upload start again from zero?

Because the page that was sending it went away. An upload you start on drive.google.com is sent by that tab. If the tab is closed, Chrome quits or crashes, the computer restarts, or Chrome unloads the tab to save memory, nothing is left to carry it on, and the next try starts from the first byte. Chrome's help says Memory Saver "deactivates tabs that you aren't currently using" and reloads them when you return. Big files are hit hardest, because they need the tab for hours.

How does Google Drive resume an upload?

With resumable uploads, a feature of the Google Drive API. Google recommends them "for large files (greater than 5 MB) and when there's a high chance of network interruption". They work like this:

  1. The uploader opens an upload session, and Drive gives it a session address.
  2. It sends the file in pieces, each a multiple of 256 KB.
  3. After an interruption, it sends an empty request to the session address. Drive replies "308 Resume Incomplete" with the range of bytes it already has.
  4. It sends the rest, starting from the next byte.

A session lasts one week: Google says "A resumable session URI expires after one week". After that, Drive replies "404 Not Found" and the upload has to start again from the beginning.

What happens if I close the tab?

On Drive's website, the upload ends and you start it again later. In Uploft's uploader, uploads stop too, and the page asks before you leave while they are running. But each file's place is saved on your computer. Reopen the uploader with the extension's toolbar icon ▸ Upload files to Drive, and a banner says how many uploads were interrupted and how much is already in Drive. Then:

  • If Chrome kept access to the files (you used Choose files, Choose folder or drag and drop), press Resume in the banner. Chrome asks for permission to read the files again, one prompt for a whole folder, and each file continues from the byte Drive confirmed.
  • Otherwise, choose or drop the same files again into the same destination folder. A file with the same name, folder path, size and modified time as an interrupted upload continues it instead of starting a new one.

What if the Wi-Fi drops or the computer sleeps?

The uploader waits and then continues. While the computer is offline, each file shows "Waiting for the network", and that time doesn't count against its retries. When the connection is back, it asks Drive how much arrived and goes on from there.

While uploads run, it also asks Chrome to stop the computer sleeping from inactivity. If the computer sleeps anyway, for example because the lid was closed, the interrupted piece is sent again after it wakes and the file continues from Drive's last confirmed byte.

What if Chrome crashes or the computer restarts?

It works the same as a closed tab. The upload list is kept in the browser's own storage, so after a restart the uploader shows the interrupted files when you open it. Resume within a week. After that Drive has dropped the session, and when you resume, the uploader starts that file again from zero.

How much is sent twice after a drop?

At most the piece that was on its way. Pieces start at 8 MB and grow up to 64 MB on fast connections, and Drive says exactly which bytes it stored, so the uploader goes on from the next one. Worked example: a whole 64 MB piece is 64 × 8 = 512 megabits, and at 20 Mbps sending it again takes 512 ÷ 20 = 25.6 seconds. Starting a 50 GB file again from zero at the same speed would take 5 hours 33 minutes.

Can it resume uploads I started on drive.google.com?

No. Those uploads belong to Drive's own page, and only Drive can carry them on. On drive.google.com the extension presses Drive's Retry button for you, keeps the computer awake and stops Chrome unloading the tab, which removes two common reasons for a restart. If that tab is closed, though, the upload is gone. For uploads that must survive a closed tab, start them in the uploader. See why Drive uploads fail or get stuck for the rest.

What are the limits?

  • Resuming needs the same file, unchanged. If its size or modified time changed, it is treated as a new upload.
  • Resume within a week, while Drive keeps the session.
  • The uploader has to be open for uploads to run. It doesn't upload in the background after its tab is closed.
  • For a folder you want kept in sync all the time, Google Drive for desktop is Google's own answer; Google says its sync can be paused and resumed at any time.
  • It runs in Chrome 116 or later on a computer, and it isn't on the Chrome Web Store yet.

Uploft is free, and its source code is public. It isn't on the Chrome Web Store yet; the home page shows what it does and what it asks for.
