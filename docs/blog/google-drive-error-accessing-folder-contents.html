Why does Google Drive say 'error accessing folder contents'?

Published 29 October 2026 · Updated 29 October 2026 · By Sai Nath

The message means the upload could not read something inside the folder you chose. Usual causes are a file another program has locked, a file your account on the computer cannot read, or a path the system can't open. Upload the subfolders one at a time: the one that fails holds the file to fix.

This guide comes from the maker of Uploft, the Chrome extension mentioned below. Google's steps link to Google's own pages and were checked on 29 October 2026; what the extension does comes from its source code. Google's help pages do not explain this exact message, so the causes below are the ones that fit a folder that cannot be read, not an official list.

Locked or system files

Start here. A folder upload reads every file inside, including ones you never open: a database another program is using, a temporary file, a file still being saved or synced. If one of them can't be read, the whole folder can report a problem even though the other files are fine. Close the programs that use the folder (editors, mail clients, photo libraries, backup tools), let any export or sync finish, and try again.

Application bundles, library files and the folder of a running program are poor choices for a Drive upload for this reason. Copy the files you want into a plain folder first and upload the copy.

Uploft leaves out three hidden system files on its own: .DS_Store, Thumbs.db and desktop.ini. Other files are read as they are.

Permissions on the local folder

The browser can only read what your account on the computer can read. A folder owned by another user, one on a network share, or one that your system has locked down can be listed and still refuse to open. Check that you can open the folder and a few of its files in your file manager. Fix the permissions there, or copy the folder to somewhere you own, such as Documents or the desktop, and upload the copy.

Google's help for Drive for desktop says the same about its own app: "You must give the selected folder read and write permissions for Drive to sync your folder." See Fix problems in Drive for desktop. The upload in a browser tab needs read access to every file.

Long paths

Deeply nested folders with very long names can be hard for the operating system to open, and a file buried in one can fail while a shallower copy works. Google's upload help doesn't state a path-length or file-name limit for the files on your computer, so the limit that applies is your system's. Move the folder closer to the top of the disk (for example Documents/Backup), shorten the longest folder names, and upload again.

Upload subfolders one at a time

This is the way to find the file. Instead of the top folder, upload its subfolders separately, and split the one that fails again. When a single small folder is left, the cause is inside it: open each file, move out the one that won't open, and upload the rest.

  1. Open the top folder in your file manager and note its subfolders.
  2. In Drive, choose New ▸ Folder upload and pick the first subfolder. Google's upload help describes folder upload and dragging folders in.
  3. Repeat for each subfolder. Note the one that fails.
  4. Split that subfolder the same way until one file or a few remain.
  5. Move the file that fails somewhere else, or fix its permissions, and upload the remaining folder.

In Uploft the same method applies with Choose folder: pick one subfolder at a time. The uploader lists every file in a chosen folder as its own item with its path, and a file that can't be sent is marked failed while the rest carry on, each failed one with a Retry button. The folder is read in full when you choose it, though. In the source code, if a file in the folder can't be read at that moment, the pick stops with an error written to the browser console, not shown on the page, and nothing from that folder is added. If choosing a folder seems to do nothing, that is the cue to split it up.

Is the problem on the Drive side?

Rule out the destination too. If you upload into someone else's folder you need permission to add files to it, and Google's help says an upload takes up space in your own Drive even when the folder belongs to someone else. Uploft reports "No access to the destination folder. Choose it again" and "No permission to add files to this folder" when the Drive folder is the issue; those messages name the Drive folder, not the one on your computer.

If the folder keeps failing in the browser, Google's own app is another way in: Drive for desktop uploads the files you drag into its folder without an open tab, and it copies a file it cannot upload to a "Lost and Found" folder on your hard drive, as its help describes.

See also why a file is unreadable when you upload.

Limits to know

  • The extension cannot make an unreadable file readable. It reports what it can, and splitting the folder is the way to find the file.
  • Google doesn't document this exact message, so the causes here are likely ones, not a confirmed list.
  • "Skip it" and "Replace it" only know files the extension uploaded (the drive.file permission), so files sent with Drive's own site can be duplicated.
  • It runs in Chrome 116 or later on a computer, isn't on the Chrome Web Store yet, and the Google sign-in is in testing, so only listed test users can sign in for now.

Uploft is free, and its source code is public. It isn't on the Chrome Web Store yet; the home page shows what it does and what it asks for.
